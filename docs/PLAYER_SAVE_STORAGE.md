# Windows 独立游戏存档

2026-10-16 用户确认的策略，仅适用于 Windows 内嵌卡带独立客户端。

- 存档保存在实际游戏 EXE 旁的 `saves/<game_id>/<install_id>/`，不跟随当前工作目录。
  现有固定卡带的 `install_id` 为 `preview_gamecli`；额外的游戏 ID 层避免不同游戏混档。
- 安装位置不可写、被锁定或包含不安全链接时明确报错，不静默回退到 AppData，
  不要求玩家通过管理员身份玩游戏。可将整个游戏目录移到可写位置。
- 存档内部格式、槽位、手动/自动/快存分类及正常保存原子写入不变。
- 固定游戏新快照的 `game_id` 保留实际游戏身份，`install_id` 保留原安装身份；
  两者不能因独立包通用的 `preview_gamecli` 而混用。旧档读取仍兼容既有身份，
  Android 私有存储路径、卡带库与预览的存档身份规则不变。
- 首次发现同一游戏的旧 AppData 存档时询问是否复制。取消不创建目标目录；
  之后可从存读档页“存档位置／旧档迁移”重新扫描。
- 迁移只复制身份、分类、槽位与文件名相符的旧档；源档保留。
  目标同名字节相同则已完成，不同则列为冲突并跳过，绝不覆盖。
  中途失败可以重试，已成功的副本保留，不重复复制。
- 扫描和复制均拒绝存档目录中的链接/重解析点、异常文件及超限文件。
  迁移与正常存档 IO 共用串行锁；客户端退出会等待已经开始的迁移写入。

卡带库宿主、编辑器预览、Android 私有存储、Editor 数据库与 `.vnproj`
保存目录不随此策略改变。此文档不等于新安装版或设备验收已通过。

退出前会等待已开始的保存完成。保存失败时保持游戏打开：自动保存开启时可重试；
关闭时可返回游戏重新保存，随后再次退出，不会因此新建自动档。放弃保存须二次确认。
