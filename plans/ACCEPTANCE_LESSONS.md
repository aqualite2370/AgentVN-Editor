# 验收经验与操作交接

本文件维护可复用的验收规则；当前进度以 `ACTIVE_TASKS.md` 顶部为准，原始失败报告保留。目标是一次完成完整功能组，避免为相同工具失误重复导入、构建和付费调用。

## 1. 原生操作必须完成证据交接

已发生的失误：目录已经通过原生选择器选中，界面也记录了输出路径，但未写入runner等待的回执。runner最终超时，后续构建没有执行。不能将界面成功等同于整条测试通过。

| 阶段 | 必须核实的事实 |
| --- | --- |
| 等待输入 | 当前request、所属PID与安装路径、目标路径、completion路径、请求时间 |
| 实际操作 | 通过获准的Computer Use或用户输入操作真实选择器 |
| 观察结果 | 有效截图或可读状态确认选择结果，证据保存到本会话目录 |
| 写入回执 | 使用本次request的ID/PID/路径，记录真实观察时间、操作方式、证据路径及SHA-256 |
| 接收交接 | 读回回执并用`validateObservedPickerReceipt`校验，观察runner接受并进入下一阶段 |
| 结束 | 分别读取功能报告和controller清理终态，不能只看其中一个汇总状态 |

操作、证据、回执、接收确认应连续完成，不在中间结束对话。回执字段以 `scripts/lib/observed-native-picker.cjs` 和实际request为准，禁止复制旧UUID、使用会话结束后的观察时间补写历史回执，或仅凭DOM字段推断原生输入已完成。回执缺失时先诊断交接，不反复选择相同目录或等待超时碰运气。

## 2. 恢复前检查现场，不能沿用旧摘要

先读取report、controller、native-input-request及completion，检查时间和所属进程身份。进程号存在不等于仍属于本轮；窗口handle也不能跨会话直接复用。

- `FINISHED`表示控制器完成，不代表job成功。
- `cleanupStatus=PASS`只证明报告范围内清理，不能消除功能FAILED。
- 终态会话不再输入；新执行使用独立目录，保留旧原件。
- 用户授权继续不等于现场仍然有效；也不需要因此重复索取已有授权。
- 无需桌面即可完成的诊断和工具修正先做，实际到原生输入边界才等待桌面可用。

## 3. 截图与输入工具的真实边界

截图结果可能同时含16×16占位图和正常画面。按返回的实际尺寸选择有效截图，并核实坐标范围；不能固定选数组第一项或依据占位图点击。

保存证据时检查data URL的真实MIME和图像字节，JPEG使用`.jpg`，PNG使用`.png`。已被回执引用的原件不得为修扩展名而覆盖：保留原字节，另存正确扩展名副本并记录说明。原生观察图也不能替代另有尺寸/DPR要求的Runtime PNG验收。

遇到前台PID缺失、窗口消失或坐标异常，先检查controller、宿主存活及窗口归属。覆盖层是观察线索，未经独立验证不能认定其导致全部历史失败。工具错误、QA错误和产品缺陷分别登记；不临时换用未获准的原生输入通道绕过边界。

## 4. 安全复用已有通过步骤

导入、保存和重启已有通过证据时，不因后续回执失败重新执行整条作者流程。复用需满足：

- 相同冻结安装及来源哈希、相同工程输入，旧阶段原报告可核验。
- 旧会话已清理；复用同QA账户/profile时核对真实账户SID与归属。
- 当前报告显式引用原报告路径、哈希和具体阶段；不能把继承证据描述为本轮新测。
- 当前仍实际验证启动及数据库恢复；导出、Player消费、矩阵及清理没有执行就保持未通过。
- 校验不成立时说明具体差异，不降级门槛。先验证续接工具的接受及拒绝分支，再启动下一原生会话。

工具的语法通过或受控测试通过不代表真实续接通过。已冻结候选不因QA脚本修正重复编译，已过矩阵和付费结果也不为增加通过数重跑。

编译可能留下脱离父进程树的VCTIP或COM进程。功能通过后仍需按QA账户SID独立枚举；发现残留保留原清理FAILED，核对PID、创建时间、SID和可执行路径后精确清理，再记录独立补证。不得按进程名广泛终止，也不为清理重跑已通过的编译/游戏；终态审计必须显式引用原失败与补证。

## 5. 报告和内容保护

状态说明必须给出当前候选、会话、通过阶段、失败点及下一项缺失证据。旧失败保持，新增更正置于当前索引顶部，不能继续传播“旧窗口仍运行”等失效信息。

原始失败日志可能含私有小说、工程内容和本机信息：保存在本机证据目录；公开经验只写机制、必要计数及定位信息，不复制原文、凭据或整份failureText。

## 6. 执行前后检查与防止重复劳动

开始一个完整功能组前，先核实四项：冻结候选及来源、当前会话真实终态、已通过且可复用的阶段、下一步真正缺失的证据。记录实际运行命令及证据目录；已存在的报告目录不能覆盖。

涉及异步构建时，保存runner、所属进程身份和报告路径。没有新输出不代表停止，先检查报告更新时间、编译子进程及日志。原构建仍活跃时不重复提交，也不通过启动新会话替代状态核查。

结束或交接前，逐项确认：

- 功能报告、controller与清理报告分别读取，标明各自状态及范围。
- 原生输入请求已被接收，或明确记录仍缺哪一步；不留“操作完了但回执未交接”的隐性断点。
- 通过阶段可追溯到版本、来源哈希及原报告；继承、受控响应和本轮实测明确区分。
- 仍运行的进程写为在途，不能报告清理PASS；终态残留按精确归属处理。
- 私有内容只留本机证据；当前任务索引写清下一项实际操作，不用重复审计或构建增加通过数量。

新工具应先验证正常与拒绝分支，尤其是过期request、异源候选、异账户和不完整证据。产品没有变化时，工具修正不触发产品重新打包；已有功能回归无需为文档修改重跑。

## 8. 先确认产品契约，再写测试断言

测试失败先区分产品缺陷、测试假设错误和环境问题。以真实入口、当前协议及已确认需求为依据，不能为让测试通过反向修改产品语义。例如，普通缺图允许占位发布的warning，不能未经需求确认改成阻断；必需开屏视频缺失的阻断也不能因此削弱。

- 通过当前可见工作区定位控件，限定可见性和所属区域；旧工具栏中仍存在的隐藏按钮不作为入口。
- 资源提示按实际类型给出缺失内容、设置位置、必需或可选属性及可用跳转；不能让背景、头像等统一提示“补充音频”。检测逻辑、定位信息和建议文案分别核对。
- 使用最小夹具覆盖变更及相邻兼容行为。名称、标签与当前协议先核实；夹具错误保留为QA失败，修正后另存结果。
- QA修正说明必须指出依据。未知原因保持未知，不能在没有失败现场数据时声称已证实根因。

## 9. 异步页面按状态等待，矩阵按实际证据汇总

弹窗挂载、资源加载和requestAnimationFrame焦点交接存在独立完成时刻。测试等待可观察的就绪状态、实际焦点及可交互性，并设有界超时；不以任意固定延时或点击后一瞬间的采样代替状态判断。产品是否需要中间帧连续性，另按既定动效要求断言，不能靠等待隐藏闪现。

- 几何、焦点、命中、裁切分别记录结果；失败时保存实际probe、视口、DPR、减少动效状态及必要截图，避免只留下无法归因的联合布尔值。
- 普通与减少动效分别验收。真实WebView参数与PNG尺寸必须相符，声明矩阵不能代替实际组合。
- 单个组合因QA问题失败时，修正工具后只补缺失部分。合并多份报告须核对候选/受测源码哈希、输入与断言契约、环境参数及组合唯一性，显式列出继承来源和差异。
- 已通过组合不重复计数；漏项、零用例和清理未结束不能算完整PASS。补测通过不改写原失败报告；覆盖汇总通过也不等于原失败运行已全部通过。

## 10. 日志结论与交付结论分开

无崩溃、剧情可玩、存档成功或清理完成，均不能单独证明所有日志无害。逐条判定应绑定本次日志、实际版本、功能时段、参考源码或精确二进制及尚缺的因果证据。参考源码只能证明其支持的分支，不能冒称厂商二进制等价或历史调用栈已确认。

当前告警不能直接套用历史白名单或用户接受的历史限制；也不为追求全绿重复设备、抓取相同来源或扩大无关审计。下一步应明确什么新证据能改变判断。确实不能回溯时保留限制及影响范围，交用户决策，不自行改成通过。

源码回归、Dev、安装包payload、实际安装消费、公开源码交付和D盘同步分别记状态。文案修正通过源码测试，不代表冻结安装器已包含；发布新补丁时核验实际最高版本、增量范围和产物来源，不重复已通过且未受影响的Runtime导出矩阵。

执行第6节检查时同时确认：本次是在修产品还是修QA、失败probe是否足够、补测是否仅补缺口、当前告警是否越界放行、交付状态是否被源码通过替代。按完整功能组推进，不把每条断言拆成独立任务，也不以反复更新计划替代实现和验收。
